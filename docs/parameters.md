# Parameters

Every parameter the pipeline takes, in the groups `--help` uses.

```bash
nextflow run main.nf --help        # this table, in your terminal
nextflow run main.nf --help_all    # and the reasoning under each parameter
```

You need one input parameter and one HMM parameter to start: exactly one of `--input`,
`--genomes` or `--proteins`, together with `--hmms`. Everything else has a working default.

The flags worth more than a line are explained in [running the workflow](running.md):
[taxonomic priors](overview.md#taxonomic-priors), [sample IDs](running.md#sample-ids),
[re-scoring](overview.md#re-scoring-finished-searches) and [dry runs](running.md#dry-run).
Completeness is covered in [what the pipeline does](overview.md#how-complete-are-your-genomes).
Per-genome values go in a [samplesheet](samplesheets.md).

## One dash or two

Nextflow keeps single-dash options for itself and gives the double-dash space to the pipeline.
`-profile`, `-resume`, `-c` and `-work-dir` configure Nextflow. Anything written as
`--name value` becomes a pipeline parameter, which is how `--genomes` and `--hmms` reach the
workflow.

Getting this backwards used to fail without complaint. `--resume` sets an unused parameter
called `resume` and then runs everything from scratch. `--profile standard` leaves you on the
default profile, so on a cluster every task lands on the login node instead of going through the
scheduler. Nextflow itself cannot warn you, because a pipeline may invent whatever `--` options
it likes and Nextflow has no list of correct spellings to check yours against.

This pipeline has that list, in `nextflow_schema.json`, and checks against it:

```
Unrecognised parameter:

  --resume   belongs to Nextflow, not to this pipeline. Write it with one dash: -resume
```

A misspelling of a real parameter gets the nearest match suggested, so `--outdr` stops the run.
It used to write your results to `results/` while you waited for them somewhere else. If a
config of your own declares parameters this pipeline does not know about, turn the check off
with `--validate_params false`.

### Input

Where the sequences come from. Give exactly one of --input, --genomes or --proteins.

| Parameter | Type | Default | Description |
|---|---|---|---|
| `--input` | file | none | Samplesheet, one row per sample, carrying its own completeness and taxonomy. |
| `--genomes` | path | none | Directory of nucleotide FASTA files (.fa, .fna, .fasta), or a glob pattern. Genes are called with pyrodigal. |
| `--proteins` | path | none | Directory of protein FASTA files (.fa, .faa, .fasta), or a glob pattern. Skips pyrodigal. |
| `--hmms` | path | none | A single concatenated .hmm file such as KOfam profiles.hmm, or a directory of individual .hmm files. |
| `--id_from_filename` | flag | `false` | Take sample IDs from file names rather than parent directory names. |

### Output

| Parameter | Type | Default | Description |
|---|---|---|---|
| `--outdir` | directory | `results` | Where final output files are written, one subdirectory per sample. |
| `--no_blimmp_log` | flag | `false` | Skip the BLIMMP debug log, which is written by default at roughly 3.4 MB per genome. |

### Sequence masking

Low-complexity regions score against many profiles for reasons that have nothing to do with homology. tantan masks them by default.

| Parameter | Type | Default | Description |
|---|---|---|---|
| `--no_masking` | flag | `false` | Skip the tantan masking step, searching the protein sequences exactly as pyrodigal predicted them. |

### Genome completeness (sigma)

BLIMMP weighs a missing KO against how much of the genome is actually there. That fraction is sigma.

| Parameter | Type | Default | Description |
|---|---|---|---|
| `--busco_lineage` | string | none | Measure completeness per sample with BUSCO using this lineage, e.g. bacteria_odb12, or auto, auto_prok or auto_euk to let BUSCO pick one per sample. |
| `--busco_downloads` | directory | none | Directory holding already-downloaded BUSCO datasets, which makes the BUSCO step run offline. |
| `--sigma` | number | none | State the completeness fraction instead of measuring it, e.g. 0.85 for a genome believed 85% complete. |

### Module detection

| Parameter | Type | Default | Description |
|---|---|---|---|
| `--taxonomy` | string | none | Which set of taxonomic priors BLIMMP scores against, e.g. cyanobacteriota. Defaults to all bacteria. |

### Re-scoring finished searches

Used only with -entry blimmp_only, which starts from HMMER tables that already exist. The search takes hours and BLIMMP takes minutes, so re-scoring should not mean re-searching.

| Parameter | Type | Default | Description |
|---|---|---|---|
| `--domtblout` | path | none | Directory of .domtblout files, or a glob such as 'results/*/*.domtblout'. |
| `--completeness` | file | none | A busco_summary.tsv from an earlier run, giving each sample the completeness BUSCO measured for it. |

### Parallelism

The HMM database is split into chunks and every genome is searched against every chunk, so these control how many jobs the run creates.

| Parameter | Type | Default | Description |
|---|---|---|---|
| `--hmm_chunk_size` | integer | none | Number of HMM profiles per chunk. Turns off the automatic sizing. |
| `--hmm_chunks` | integer | none | Total number of chunks, with the chunk size worked out to match. |
| `--max_concurrent` | integer | none | Cap on how many jobs are submitted to the scheduler at once. Defaults to 100, which is Nextflow's own default for grid executors. |

### Testing at reduced scale

| Parameter | Type | Default | Description |
|---|---|---|---|
| `--subsample_genomes` | integer | `0` | Use only the first N inputs. 0 means all of them. |
| `--subsample_hmms` | integer | `0` | Use only the first N HMM profiles. 0 means all of them. |

### Generic options

| Parameter | Type | Default | Description |
|---|---|---|---|
| `--help` | flag | `false` | Print the parameter list and exit. |
| `--help_all` | flag | `false` | Print the parameter list with the full explanation of each, and exit. |
| `--validate_params` | flag | `true` | Stop the run on a parameter this pipeline does not recognise. |
